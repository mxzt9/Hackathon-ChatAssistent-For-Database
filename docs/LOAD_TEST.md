# Нагрузочная проверка

Запустите сервер и дождитесь `model: ready` в `/api/health`, затем:

```powershell
python -m pip install -r requirements-dev.txt
python scripts/load_test.py --url http://127.0.0.1:8000
```

Скрипт проверяет HTTP endpoint `/api/health`, затем отправляет вопросы через
`POST /api/query`. Используются подсчёты студентов, преподавателей и заявлений,
а также средняя оценка. В режиме model выполняется 16 вопросов в серии при
параллельности 1, 4, 8 и 16; в local — 100 вопросов при 1, 10, 25, 50 и 100.
После серии с ошибками увеличение нагрузки прекращается.

`concurrency` — максимальное число одновременно отправленных запросов.
`requests_per_second` включает все ответы, в том числе отказы; успешная
пропускная способность считается отдельно. p95 означает, что 95% запросов
завершились не дольше указанного времени. Задержка включает очередь сервера.

## Пример измерения с Qwen

Результаты локального запуска пользователя 8 октября 2026 года:

| Одновременные запросы | Всего | Успешных | Ответы 503 | p50, мс | p95, мс |
|---|---:|---:|---:|---:|---:|
| 1 | 16 | 16 | 0 | 599 | 893 |
| 4 | 16 | 16 | 0 | 2323 | 2477 |
| 8 | 16 | 5 | 11 | 57 | 2754 |

При параллельности 1–4 получено около 1,7 успешного ответа в секунду.
При 8 одновременных запросах очередь заполняется: один вопрос выполняется,
четыре ждут, остальные получают 503 «Модель занята».
Низкий p50 этой серии объясняется быстрыми отказами, а не ускорением Qwen.
HTTP-проверка завершилась без ошибок во всех сериях вплоть до 100 запросов одновременно.

Это короткий тест простых вопросов, а не установленный предел нагрузки.
Сложные запросы, другой компьютер и длительная работа могут дать другие результаты.
