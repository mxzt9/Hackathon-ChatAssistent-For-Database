# Чат с PostgreSQL

Учебный прототип: администратор подключает PostgreSQL, выбирает разрешённые
таблицы и колонки, затем отправляет посетителям ссылку на чат. Qwen составляет
SQL по выбранной схеме, сервер проверяет запрос и выводит результат из БД.
Чат можно встроить на другой сайт через iframe или плавающую кнопку.

## Запуск

Нужны Python 3.12 и PostgreSQL. Для готовой учебной БД используется Docker Desktop.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-qwen.txt
Copy-Item .env.fullstack.example .env
docker compose up -d postgres
python -m ml.qwen --download-only
python run.py
```

Копирование `.env` нужно только при первом запуске. Если файл уже есть, сохраните
свои настройки. Откройте http://127.0.0.1:8000. Модель загружается в фоне;
готовность можно проверить через http://127.0.0.1:8000/api/health:
поле `model` должно стать `ready`.

Qwen выбирает CUDA, если она доступна, иначе работает на CPU. Для CUDA нужна
совместимая сборка PyTorch; если GPU не определяется, проверьте
`python -c "import torch; print(torch.cuda.is_available())"`.

Данные подключения к учебной БД:

| Поле | Значение |
|---|---|
| Адрес | `127.0.0.1` |
| Порт | `5432` |
| База | `university` |
| Пользователь | `assistant_ro` |
| Пароль | `change_me` |
| SSL | отключён |

Docker заполняет БД при первом запуске и сохраняет её в volume.
Готовый чат с этой БД: http://127.0.0.1:8000/demo.

## Как показать проект

1. Подключите БД на главной странице.
2. Включите нужные таблицы и отметьте колонки для публичного чата.
3. Нажмите «Сохранить и создать ссылку».
4. Откройте ссылку и задайте вопрос, например «Сколько всего студентов?».
5. Раскройте SQL и сравните ответ с запросом к БД.

Ссылка `/setup/<id>` позволяет менять доступ. Ссылка `/chat/<id>` открывает чат.
Панель также выдаёт код iframe и кнопки виджета. Подключения и их пароли хранятся
в памяти сервера; после перезапуска подключения создаются заново.

Для доступа с другого компьютера задайте `APP_HOST=0.0.0.0` в `.env` и используйте
IP сервера вместо `127.0.0.1`.

## Структура

```text
app/          API, настройки, подключения и выполнение запросов
ml/           загрузка Qwen, промпт и подготовка схемы
sql/          правила доступа и проверка SQL
frontend/     панель администратора, чат и встраиваемый виджет
database/     схема, учебные данные и создание большой БД
scripts/      проверка доступности и нагрузки сервера
tests/        автоматические проверки
docs/         презентация и инструкции для демонстрации
run.py        запуск FastAPI
```

HTML, CSS и JavaScript раздаёт FastAPI; сборка фронтенда не требуется.
Зависимости разделены по назначению:

- `requirements.txt` — сервер без модели;
- `requirements-qwen.txt` — сервер и Qwen;
- `requirements-dev.txt` — тесты и генератор большой учебной БД.

Модель работает в отдельном процессе, чтобы сбой CUDA не завершал HTTP-сервер.
Одновременно выполняется один вопрос, ещё четыре могут ждать. При заполненной
очереди сервер возвращает 503. Веса находятся в стандартном кэше Hugging Face.
Windows/CUDA использует чтение весов без mmap для обхода обнаруженного сбоя.

## Возможности и ограничения

Поддерживаются таблицы схемы `public` и простые SELECT с JOIN, GROUP BY, HAVING
и ORDER BY. Сервер проверяет разрешения на таблицы, колонки и функции,
ограничивает число строк и выполняет SQL в read-only транзакции с таймаутом.
Закрытые колонки видны в настройках, но недоступны для выбора. Оценки и
идентификаторы учащихся разрешены только в агрегатах.

Промпт состоит из коротких общих правил, выбранной схемы и вопроса. Из 4096
токенов 256 резервируются для SQL; слишком большая схема отклоняется.
История чата отображается в браузере, каждый вопрос обрабатывается отдельно.
Модель может ошибаться в смысле запроса: проверка SQL не гарантирует правильный ответ.
WITH, вложенные SELECT, UNION, оконные функции и пагинация не поддерживаются.

Для демонстрации без модели установите `requirements.txt` и задайте
`SQL_BACKEND=local`: доступны ограниченные шаблоны вопросов по университетской БД.
Контейнер приложения (`docker compose --profile server up -d`) использует этот режим.

## Проверки

```powershell
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
python -m pytest
```

Для работающего сервера: `python scripts/smoke_server.py`.
Проверить модель из консоли:

```powershell
python -m ml.qwen --schema-file database/schema.sql --policy sql/whitelist.json --question "Покажи преподавателей по математике"
```
